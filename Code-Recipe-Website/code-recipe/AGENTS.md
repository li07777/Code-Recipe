# Code Recipe｜程式碼食譜 — AI 開發協作規範

> 本文件是本專案的主要開發規範。任何 AI 或貢獻者在新增、修改程式食譜或網站程式前，必須先閱讀本文件。若規則與既有實作衝突，先指出差異，再進行最小必要修改；不得擅自大量改寫。

## 1. 專案目標與範圍

Code Recipe 是以繁體中文撰寫的程式學習知識庫，將程式概念整理為可以搜尋、分類、複製與理解的「食譜」。第一階段支援 **Python、Java、C++**，內容以初學者常用的演算法、資料結構與基礎程式技巧為主。

核心目標：
1. 使用者可以依語言、分類、難度與關鍵字找到食譜。
2. 每篇食譜統一提供用途、前置知識、輸入與輸出、解題步驟、完整可執行程式碼、範例執行結果、時間與空間複雜度、常見錯誤。
3. 未來新增內容時，主要新增資料檔、更新索引，不應為每篇食譜另寫一份頁面 HTML。
4. 網站能以 GitHub Pages 靜態部署，不依賴伺服器、付費 API、金鑰或建置步驟。

非目標（第一版不製作）：帳號登入、雲端儲存、線上程式執行器、AI 即時聊天、後端資料庫。

## 2. 技術選擇

- HTML5、CSS3、原生 JavaScript（ES Modules 可用，但不要求框架）。
- 食譜資料採 UTF-8 JSON 檔，並使用 `recipes/index.json` 維護可載入的食譜檔案清單。
- 使用 `fetch()` 讀取 JSON；網站應透過 HTTP(S) 預覽，不能以 `file://` 開啟當作驗收。
- GitHub Pages 須支援專案子路徑，例如 `https://<account>.github.io/code-recipe/`。站內資源、頁面與 fetch 路徑使用相對路徑，禁止硬編碼 `/css/style.css` 等網域根目錄路徑。
- 除非需求清楚，避免引入外部函式庫；若引入，須記錄用途、版本、授權與離線失效時的行為。

## 3. 資料夾結構

```text
code-recipe/
├── AGENTS.md                 # AI 開發規則（本文件）
├── README.md                 # 專案介紹、使用說明與部署資訊
├── index.html                # 首頁：搜尋、篩選、食譜卡片
├── recipe.html               # 共用食譜詳細頁，透過 ?id= 指定內容
├── css/
│   └── style.css             # 全站樣式與 RWD
├── js/
│   ├── app.js                # 首頁讀取、搜尋、篩選
│   ├── recipe.js             # 詳細頁載入與複製程式碼
│   └── data.js               # 共用資料讀取與驗證函式
├── recipes/
│   ├── index.json            # 食譜清單：{ "files": ["bubble-sort-python.json", ...] }
│   ├── bubble-sort-python.json
│   ├── linear-search-java.json
│   └── factorial-cpp.json
└── assets/
    └── images/              # 專案自行製作或有合法授權之圖片
```

不得將私人檔案、API keys、課堂未授權教材或 `.env` 上傳至公開儲存庫。

## 4. UI 與視覺設計

- 定位：清爽、易讀、有一點料理食譜的趣味，不犧牲技術內容的清晰度。
- 文案：臺灣繁體中文；程式語言、演算法專有名詞可中英並列，例如「氣泡排序（Bubble Sort）」。
- 色彩：主色 `#6757C8`（紫）、強調色 `#F3A76B`（暖橘）、背景 `#F8F7FC`、卡片 `#FFFFFF`、內文 `#242338`。
- 字體：系統無襯線字；程式碼採系統等寬字體。對比度、字級與行高優先於裝飾。
- 元件：頂部導覽、網站介紹、搜尋欄、語言與分類篩選、食譜卡片、詳細頁、頁尾。
- 標籤統一：語言 `Python` / `Java` / `C++`；難度 `Beginner` / `Intermediate` / `Advanced`；分類採 §5 指定值。
- 支援桌面與手機（建議檢查 360px、768px、1280px）；長程式碼區塊須可水平捲動、不破版。
- 互動具鍵盤可操作性、可見 focus、表單 label、圖片 alt、清楚的錯誤與空結果提示。
- 為避免注入風險，JSON 文字內容以 `textContent` 或安全的 DOM API 呈現，不得把不受信任的 JSON 直接插入 `innerHTML`。

## 5. 食譜分類、命名與唯一性

允許分類（`category`）：
- `basics`：基礎語法
- `sorting`：排序
- `searching`：搜尋
- `data-structures`：資料結構
- `file-io`：檔案處理
- `algorithms`：其他演算法

每份食譜用 **一種語言、一個主題** 表示。
- 檔名：`<topic-slug>-<language-slug>.json`，一律小寫英文字母、數字與連字號，例 `bubble-sort-python.json`、`linked-list-cpp.json`。
- `language-slug` 僅可為 `python`、`java`、`cpp`。
- `id` 必須與檔名去除 `.json` 後完全一致，且全站唯一。
- 同一個演算法的三種語言版本使用同一 `topic`，例如 `bubble-sort`，便於後續跨語言比較。
- `recipes/index.json` 中的檔案名稱不得重複、不得引用不存在的檔案。

## 6. 食譜 JSON 必要結構

每份 JSON 必須包含下列欄位，不得自行刪改既有欄位名稱或型別：

```json
{
  "id": "bubble-sort-python",
  "topic": "bubble-sort",
  "title": "氣泡排序（Bubble Sort）",
  "language": "Python",
  "category": "sorting",
  "difficulty": "Beginner",
  "summary": "透過交換相鄰元素，將數列由小到大排序。",
  "prerequisites": ["陣列（串列）", "迴圈", "條件判斷"],
  "input": "整數串列，例如 [5, 2, 8, 1, 3]",
  "output": "排序後的整數串列 [1, 2, 3, 5, 8]",
  "steps": ["比較相鄰元素", "若左邊較大則交換", "重複直到完成排序"],
  "code": "def bubble_sort(arr):\n    ...",
  "sampleInput": "[5, 2, 8, 1, 3]",
  "sampleOutput": "[1, 2, 3, 5, 8]",
  "timeComplexity": { "best": "O(n²)", "average": "O(n²)", "worst": "O(n²)" },
  "spaceComplexity": "O(1)",
  "complexityNotes": "未加入提前結束判斷的原地氣泡排序。",
  "commonMistakes": ["內層迴圈邊界寫錯造成索引越界"],
  "tags": ["array", "comparison", "sorting"]
}
```

備註：範例 `code` 中的 `...` 只是 schema 說明佔位符，**正式食譜不得使用佔位碼**，必須改為完整可執行的程式碼。`sampleInput` 及 `sampleOutput` 依真實程式運作填寫。若無有意義的輸入，使用空字串並註明說明；不得偽造執行結果。

## 7. 內容品質與程式正確性

- `summary` 以一至兩句話說明「這段程式解決什麼問題」。
- `steps` 至少 3 步，應與實際程式流程一致。
- `code` 應為完整、獨立、可理解的最小範例，包含必要 import / include、主程式或呼叫示例。
- Python 明確使用 Python 3；Java 以標準 `public class Main` 為基準；C++ 以 C++17 為基準，避免非標準的 `<bits/stdc++.h>`。
- 有多種做法時，複雜度要對應本食譜實際使用的版本；必要時補充邊界條件、是否原地修改、是否有序資料前提。
- 未經執行驗證，不得寫「已測試成功」；能執行時，使用真實執行結果，不能執行時明確標示「待測試」。
- 禁止虛構引用、複製未授權教材或整篇照搬第三方文章；外部參考需註明來源。

## 8. AI 新增食譜的標準作業流程（SOP）

1. **先讀規範**：閱讀 `AGENTS.md`、`README.md`、`recipes/index.json`，確認現有檔案與命名規則。
2. **檢查重複**：搜尋現有 `id`、`topic` 與語言；若相同食譜已存在，改成修改既有內容，勿建立重複頁。
3. **建立資料**：依 §6 完整填入 JSON，檔名、`id`、`topic` 與語言保持一致。
4. **驗證正確性**：檢查 JSON 語法與必要欄位；能執行時測試程式碼，確認範例輸出、邊界案例與複雜度。
5. **更新索引**：在 `recipes/index.json` 的 `files` 陣列加入新檔案名稱，不覆寫其他項目。
6. **檢查呈現**：確認首頁卡片、搜尋、語言／分類篩選、詳細頁及複製程式碼功能正常；檢查手機版。
7. **回報變更**：列出新增／修改檔案、測試方法與結果、未完成或待確認事項。

**不得**為了新增單篇食譜，複製新的 `recipe.html` 或硬編碼首頁卡片。若欄位格式必須變更，需同時更新本文件、讀取邏輯和既有資料相容性，並在變更報告說明。

## 9. AI 修改網站程式的規則

- 優先小幅修正；避免無需求的大規模重構。
- 不得任意刪除既有食譜、功能或使用者內容。
- 修改 CSS 須維持已定義的視覺變數與 RWD；修改 JS 不得破壞其他語言與分類篩選。
- 不得儲存秘密、使用者個資或加入未要求的追蹤腳本。
- 若發現規格不明、內容衝突或檔案缺失，先清楚指出；可提出安全、最小影響方案。
- 所有新連結與圖片路徑都應在 GitHub Pages 專案子路徑下正常運作。

## 10. 驗收條件（Definition of Done）

完成一個版本前應逐項檢查：

- [ ] 首頁與詳細頁在 GitHub Pages 上能正常載入，無 404。
- [ ] Python、Java、C++ 至少各有一份真實食譜。
- [ ] 每篇資料符合 JSON schema 並能從 `recipes/index.json` 載入。
- [ ] 搜尋、語言／分類／難度篩選正常，無結果時有提示。
- [ ] 詳細頁包含必備欄位、程式碼可複製、無危險 HTML 注入。
- [ ] 程式碼範例與輸出一致；若尚未執行測試，明確標註。
- [ ] 手機與桌面版無明顯破版，鍵盤操作可用。
- [ ] 新增一份食譜不需修改首頁 HTML 或複製詳細頁模板。
- [ ] README 記載網站簡介、資料夾、使用方式、GitHub Pages 連結及後續新增方式。
- [ ] AI 依 §8 進行一次新增食譜的實測，記錄修改檔案及驗證結果，可作為作業報告證據。

## 11. 提供給 AI 的標準任務模板

> 請先閱讀專案根目錄的 `AGENTS.md`，並依照其規則為 Code Recipe 新增「二分搜尋（Binary Search）」的 Java 食譜。請先檢查是否重複，建立完整 JSON、更新 `recipes/index.json`、驗證程式碼與範例輸出，最後回報你新增或修改了哪些檔案、哪些項目已測試、哪些項目仍待確認。不要建立獨立的新 HTML 頁面，也不要更動既有食譜。

## 12. 版本與規則調整

本規則適用於第一版。之後增加新語言、分類或欄位前，先確認對資料、介面及既有頁面的影響，更新 `AGENTS.md` 與 `README.md`，再實施修改。重要調整應在 Git commit 訊息中簡述原因。
